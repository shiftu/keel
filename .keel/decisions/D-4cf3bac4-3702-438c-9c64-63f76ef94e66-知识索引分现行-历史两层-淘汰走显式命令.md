## 背景

`knowledge/INDEX.md` 原本全量渲染三张表，superseded / retired / archived 一条不落。
索引的长度跟 commit 数无关，跟对象数有关；而对象里唯一只增不减的，正是这三类
「不再声称适用」的结论——按 §8.1 它们一条都不能删，于是索引里现行结论会被历史淹掉，
整文件重写也放大了 git diff。

同时记忆缺一个归档的命令入口：状态机里有 `archived`，却只能手改 frontmatter。

## 决定

索引分两层：现行结论出全表，历史结论只出一张最多四行的计数表。
历史的判据统一为 `IsHistory()`，`why --history` 用同一组函数。
`knowledge.index_history: true` 展开逐条清单。

补 `keel archive <M-…> --reason`，与 `keel retire` 对称。
`keel review` 增加 `memory_archive_candidate` 与 `index_pressure` 两个候选 code。

## 备选与理由

**按 scope 分组**（§3.6 原措辞）：否决。scope 是一串 glob 不是单一主题，分组键不确定；
让索引在对象上千后仍可读的是分层，不是分组。§3.6 的措辞一并改了。

**按时间自动归档**：否决。状态转换只有两个入口——`keel verify` 真跑完一次验证器，或人显式改。
自动归档是第三个入口，而且是最坏的一种：它在没有任何新证据的前提下改变结论的效力。时间不是证据。

**把 `index_pressure` 做成 check 门禁**：否决。会产生「为了过门禁而删记忆」的反向激励。
它只进 review。

**把 `stale` / `disputed` 记忆也算历史**：否决。它们是提醒，藏进历史区等于替人做了「不用管」的判断。

## 后果与验证方式

`proposed` 决策从此出现在 `keel why` 的默认输出里（原先按 `!IsActive()` 被归进历史）。
这是修 bug：等人拍板的方案该被看见。formats.md §3 的措辞一并改了。

`render.KnowledgeIndex` 多收一个 `store.Config` 参数。已有仓库的 `keel.yaml` 缺新字段时
由 `DefaultConfig()` 兜底，无需重新 init。

验证方式：`go test ./...`，三个新 testscript 夹具 `knowledge-index-layers` /
`memory-archive` / `review-archive-candidates` 分别盯分层、归档转换、候选与压力信号。
