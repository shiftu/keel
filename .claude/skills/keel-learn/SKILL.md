# 记一条经验

## 什么时候触发

- 踩了坑并找到绕法
- 发现了非显而易见的事实（某个行为只在特定环境成立）
- 验证结果推翻了之前的说法（写成反例）

**没有值得留下的东西就不写。** 零记录结束是正常的，不要为了凑数把同一件事换个说法记三遍。

## 步骤

1. **先查有没有同类。**

   ```
   keel why --query <关键词>
   ```

   已有同类：补充它的适用条件，或者当你的结论与它冲突时，把冲突写清楚而不是覆盖。

2. **写候选记忆。** 一条只说一件事：

   ```
   keel note "<一句话事实>" \
     --tag <主题> --path <相关文件> --kind gotcha \
     --condition environment=<在什么条件下成立> \
     --by agent:<你是谁>
   ```

   `--kind`：`gotcha` 坑、`fact` 事实、`pointer` 外部资料、`counterexample` 反例。

3. **写清适用边界。** 「SQLite WAL 在 NFS 上锁失败」是有用的；「SQLite 有问题」不是。
   没有条件限定的记忆会在不该出现的时候被召回。

## 状态说明

新记忆一律是 `candidate`：可以被检索到，但在有证据之前，不会被当成项目规则注入。
把它升成 `verified` 需要关联的验证证据，那是 `keel-review` 的事，不是写的时候自己声明。

## 不要做的事

- 正文超过 20 行说明它其实是一次决策，走 `keel decide`。
- 不要删掉失败和反例，它们也是长期记忆。
